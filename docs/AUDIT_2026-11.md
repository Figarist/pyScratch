# Аудит pyScratch і план робіт (2026-11-17)

Аудит провели 4 агенти (Sonnet ×3, Haiku ×1). Вони лише читали код і запустили тести: усі 12 наборів у `npm test` пройшли.
Важливо: Python-коду в репозиторії немає. «Python-сторона» — це Python-подібний DSL, який розбирає `js/compiler.js`.

## Етап 1 — Коректність Scratch-виходу (3–5 днів)
- Перевіряти значення полів через whitelist (EFFECT, STYLE, DRAG_MODE, STOP_OPTION, KEY_OPTION, math OPERATOR тощо) і давати зрозумілу CompileError (compiler.js:1011-1549).
- Забороняти motion- і looks-блоки на Stage та stage-only блоки на спрайтах.
- Кидати помилку при конфлікті імен глобальної і локальної змінної.
- Перевіряти кількість аргументів кастомних блоків; додати `%b` (булеві аргументи).
- Колір `"#rrggbb"` перетворювати на shadow 9 лише у COLOR-входах (compiler.js:~790).
- Для mp3 записувати реальні rate і sampleCount; SVG зберігати як байти, щоб не ламався md5.
- Інспектор: повний список hat-опкодів, щоб не було хибних «orphan scripts»; звіт про відсутні ассети; перевірка загального розміру .sb3.

## Етап 2 — DSL / компілятор (3–5 днів)
- Продовження рядка всередині `()` і `[]` та через `\`.
- Зрозумілі повідомлення для `return`, `break`, `class`, `import`, `lambda`, `**`, f-рядків і тернарного `x if c else y`.
- Номер стовпця (`col`) у токенах і CompileError, щоб підсвічувати місце помилки.
- Escape-послідовності `\r \\ \xNN \uNNNN`; невідома послідовність має давати помилку, а не мовчки спотворювати рядок.
- Ідентифікатори з будь-якими літерами Unicode (`\p{L}`).
- Перевірка кратності відступу 4 пробілам (або виправити текст помилки).
- Зберігати `#`-коментарі в `target.comments` в обидва боки.
- Задокументувати розбіжності з Python: `//` і ділення на 0, точність великих int, області видимості.

## Етап 3 — Сайт: продуктивність, безпека, a11y (2–4 дні)
- `defer` для 8 скриптів (~480 KB); jszip і inspector вантажити ліниво; мініфікація або один бандл.
- CSP через `<meta>`; inline-скрипти винести в файли; SRI або self-host для GoatCounter.
- Доступність: `aria-label` для textarea редактора, `role="status" aria-live` для статусу, видимий `:focus-visible` замість `outline:none` (style.css:519,703,1006,1048).
- Мобільна версія: брейкпойнт 480px, тач-цілі ≥44px, екранні стрілки для ігор, `prefers-reduced-motion`.
- Перемальовувати DOM лише при змінах (varsWatch, підсвітка), з debounce або rAF.
- Share-посилання: обмежити довжину коду в `?code=` і не передавати query в аналітику.

## Етап 4 — i18n і SEO (2–3 дні)
- Винести ~150 жорстко зашитих українських рядків із app.js у i18n.js.
- У en/ru HTML писати статичний текст відповідною мовою; додати `data-i18n-title` до посилань шапки.

- `og:locale` та alternate, JSON-LD для en/ru, окрема PNG-картинка 1200×630 з `og:image:alt`.
- robots.txt із Sitemap; генерувати lastmod у CI.
- Опублікувати DSL-довідник і приклади як окремі HTML-сторінки (більше сторінок для пошукових запитів).
- favicon, manifest, `<noscript>`, примітка про аналітику (приватність).
